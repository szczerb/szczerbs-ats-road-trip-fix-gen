# Map structure and compatibility

Inspected: 2026-10-17. The SCS map tutorial describes the shared ATS/ETS2 editor file model, but its examples are older and must not be treated as a complete ATS 1.61 map specification. **Documented** cites SCS; **observed locally** requires local files or a game test; **hypothesis** needs testing; **unknown** lacks sufficient evidence. No local game or map files were inspected for this note.

## Definitions and placed world

- **Documented:** The map editor divides a map into sectors. SCS's tutorial shows a map header (`.mbd`, `.set`, `.epa`) and a group of binary sector files (`.aux`, `.base`, `.data`, `.desc`, `.layer`, sometimes `.snd`). It says these files collectively encode roads, signs, placements, cities, companies, and other map content. Reading a text definition alone cannot establish that an appropriate item is placed in the world. [Saving, Loading, Sectors, and Files](https://modding.scssoft.com/wiki/Tutorials/Map_Editor/Introduction_to_the_Map_Editor/Saving%2C_Loading%2C_Sectors%2C_and_Files)
- **Documented:** `company_permanent` holds non-instance company data. A `company_def` normally under `/def/company/<company>/editor/<city>.sii` associates a company with a city token and a prefab token; SCS says this implementation permits one occurrence of that depot prefab per city. A matching text definition is thus one part of the depot linkage, while the map still needs an appropriate placed prefab. [company_permanent](https://modding.scssoft.com/wiki/Documentation/Engine/Units/company_permanent), [company_def](https://modding.scssoft.com/wiki/Documentation/Engine/Units/company_def)
- **Documented:** Prefabs are map assets that may represent roads, company docks, services, or gas stations. Their control nodes connect to other map assets and AI traffic; spawn points and trigger points define possible player interactions. The cited locator page explains asset creation, not every ATS 1.61 runtime rule. [Prefab locators](https://modding.scssoft.com/wiki/Documentation/Tools/SCS_Blender_Tools/Locators/Prefab_Locators)

## Compatibility implications

- **Documented (historical ETS2 1.4.1):** SCS describes maps assembled from sectors across archives, subject to file overloading. The same guide documents additive list files for selected categories, such as `city.<mod_id>.sii`, and warns about conflicting unit names. Resource replacement and explicitly supported list aggregation are different mechanisms; the guide does not establish arbitrary attribute merging or a complete ATS 1.61 rule set. [SCS 1.4.1 modding guide](https://modding.scssoft.com/wiki/Games/ETS2/Modding_guides/1.4.1)
- **Hypothesis:** A map expansion may lack Road Trip support in text definitions, placed map items, prefab assets, or more than one of these. Classify the failing layer before proposing a patch. Missing courier jobs and missing car fueling should be investigated independently.
- **Documented:** ATS/ETS2 packages may contain conditional `base` and `dlc_` parts. A candidate definition path needs to be checked in the parts mounted for the player's DLC set. [Mod manager](https://modding.scssoft.com/wiki/Documentation/Engine/Mod_manager)
- **Unknown:** The exact 1.61 path override and load-order behavior for the target map stack, and whether a text-only patch can repair any specific station or depot, remain unverified. Record duplicate virtual paths across packages, active package order, and an in-game result. Avoid copying binary sectors into a generated patch before understanding their scope and ownership.
