## Source-code comparison

**Observed locally — 2026-10-18:** the ignored comparison set includes `local_outputs/work/2026-10-17_22-11-10/sector-parser/MapItemSerializer.cs`, `PrefabSerializer.cs`, `ServiceSerializer.cs`, `TriggerSerializer.cs`, `TruckLib-Enums.cs`, and `local_outputs/research/overlap/PpdSpawnPoint.cs`, `PpdPrefabDescriptor.cs`, `Sector.cs`. They are local research copies, not tracked files. The following is a bounded expression check, not a copyright determination:

- `map_sector.py:152-176` reads the same serialized prefab field order shown in `PrefabSerializer.cs` (model, variant, parts, nodes, slave references, ferry, origin, terrain pairs, semaphore token); `:175-177` similarly follows `ServiceSerializer.cs`. The parser's kind numbers also match `TruckLib-Enums.cs`. These are binary-layout facts needed for interoperability. The Python implementation uses a compact `_Reader`, byte skips for opaque fields, preserved original slices, strict extent/finite/UID validation, nesting limits, and explicit unsupported-kind failure. The C# source uses typed object serializers and object graphs. I found no shared nontrivial expression or direct line translation in these reviewed routines. The broad ordered kind dispatch follows numeric kind order and is a provenance consideration, not evidence by itself of copied expression.
- `ppd.py:17-54` interprets the 96-byte header and 32/36-byte spawn records whose field order appears in `PpdPrefabDescriptor.cs` and `PpdSpawnPoint.cs`. Its checks for extents and finite transforms, selective GAS counting, and `:58-105` byte-preserving duplication are Python-specific. No C# routine for this selective edit was identified in the comparison set.
- `rest_stops.py:57-136` parses trigger records, validates graph topology/geometry, and retargets exact action-token bytes. The reviewed TruckLib PPD/trigger/map source defines record layouts and typed deserialization; I did not find its polygon validation, distance policy, source-neighbor search, or mutation algorithm copied into Python. `map_sector.py` and `rest_stops.py` openly cite their format research. Comparison was limited to these higher-risk modules and the named C# sources; it was not an automated similarity proof for all 29 Python modules or every upstream revision.

## Negative findings and limits

**Observed locally:** neither current tracked paths nor reachable historical paths contain `.scs`, `.zip`, `.ppd`, `.base`, `.sii`, `.cs`, `.exe`, `.dll`, PDFs, screenshots, game logs, profiles, saves, or downloaded extractor binaries. Only project source, docs, small JPEG exports, examples, and synthetic tests are versioned. `.gitignore:3-4` excludes `local_inputs/` and `local_outputs/`; an ignored `Zone.Identifier` sidecar is not in the Git object set. The checked reachable Git object graph does not establish what might exist in unpushed external refs or future generated-release attachments.

**Observed locally:** the 534-text-blob scan found zero credential-assignment patterns, private-key PEM blocks, and email addresses in file bodies; scanning 32 commit messages found zero such patterns. Six `sk-...` pattern hits across historical versions of one Markdown heading were false positives from the anchor for “low-risk…”; no candidate secret was found. A pattern scan cannot prove absence of arbitrary credentials embedded in prose or images. Commit-header identity is the user's intentional placeholder, as corrected above; it is not a private-mailbox finding. Binary JPEG scan found no APP1/EXIF metadata; FFmpeg comment markers occur in some exports.

**Unknown:** the legal treatment of the format-informed code, every referenced tool's exact license at the inspected source state, trademark/trade-dress implications, and rights to redistribute separately generated `.scs` archives that include transformed source bytes. A public source repository and separately published generated mods have different content inventories. This review provides no basis to call those external mod archives safe for redistribution.
