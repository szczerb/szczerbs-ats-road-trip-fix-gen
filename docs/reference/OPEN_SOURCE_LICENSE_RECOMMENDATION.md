# Open-source license recommendation

**Research date:** 2026-10-18. **Current decision:** the maintainer has selected **AGPL-3.0-only**; [ADR-0016](../architecture/decisions/ADR-0016-license-project-under-agpl-v3.md), [LICENSE](../../LICENSE) and [LICENSING.md](../../LICENSING.md) implement it. The earlier policy comparison below is historical and is superseded by that choice. This remains a provenance and compatibility assessment, not a legal determination.

## Historical recommendation after the deeper audit

**Project recommendation, not applied: MIT** for straightforward reuse and a low-maintenance local utility, accepting closed commercial forks. The [deeper integrated assessment](IMPLEMENTATION_INDEPENDENCE_ASSESSMENT.md) and its two technical reports found no obvious substantial translated routine in the inspected code/source snapshots; research access and matching format facts do not by themselves establish a whole-project GPL obligation. This is bounded technical evidence, not legal certification.

**MPL-2.0** is the alternative if distributed changes to existing project files should remain available under an open license. **Apache-2.0** adds explicit contributor patent terms and more notice work; it is incompatible with GPLv2-only combined derivatives. **GPL-2.0-only** remains a deliberate strong-copyleft option and the compatible fallback if a relevant GPLv2-only adaptation is established. A claimed GPLv2-only adaptation cannot simply be relicensed as MIT, MPL, Apache or GPLv3. GPLv3 may be chosen for code whose actual rights permit it; no upstream later-version permission is assumed here.

The initial TASK-0029 preference for GPLv2 was conservative and preceded the complete parser/helper comparison. It is not a finding that this project is a TruckLib port. Read [the maintainer comparison](MAINTAINER_LICENSE_CHOICES.md) for distribution, patents, contributions, relicensing and concrete scenarios. At that review milestone no root license had been applied; the subsequent AGPL decision above now governs.

## Evidence and limits

- **Observed locally — current workspace, 2026-10-18:** `README.md` describes a Python 3.11+ standard-library tool. `src/ats_road_trip/archive.py` executes a separately installed sk-zk Extractor process for HashFS; the executable and ZIP are ignored under `local_outputs/`. `THIRD_PARTY_NOTICES.md` identifies TruckLib, TruckLib.Models, and TruckLib.Core as research sources. `src/ats_road_trip/map_sector.py`, `overlap_fuel.py`, `rest_stops.py`, and `courier_locations.py` document particular source-guided layouts. At the audit baseline there was no root `LICENSE`; ADR-0016 subsequently adds it. These facts narrow the review; neither separate-process use nor an “independently written” description proves that every parser is copyright-independent.
- **Documented — upstream pages inspected 2026-10-18:** [TruckLib's README](https://github.com/sk-zk/TruckLib) says GPL v2. The [TruckLib](https://github.com/sk-zk/TruckLib/blob/master/LICENSE), [TruckLib.Models](https://github.com/sk-zk/TruckLib.Models/blob/master/LICENSE), [TruckLib.Core](https://github.com/sk-zk/TruckLib.Core/blob/master/LICENSE), and [Extractor](https://github.com/sk-zk/Extractor/blob/master/LICENSE) repository listings identify GPL-2.0 and link GPLv2 license files. TruckLib's [project file](https://github.com/sk-zk/TruckLib/blob/master/TruckLib/TruckLib.csproj) points its package license to that file. These pages establish the GPLv2 baseline, but a generic GPLv2 text or GitHub classifier alone does not establish an `or-later` grant. Extractor's [2026-07-29 release](https://github.com/sk-zk/Extractor/releases/tag/2026-07-29) is the separately downloaded version recorded by the workspace.
- **Observed locally — historical source snapshots, 2026-10-18:** the saved GitHub tree API responses at `local_outputs/research/overlap/trucklib-tree.json`, `trucklib-models-tree.json`, and `trucklib-core-tree.json` report tree SHAs `c42dbe4f2d6bfb7b87c9ff1199c3cf5b7d1e27b0`, `6f09e0eb5c687202ffde0595e434675c455830e8`, and `85e810f66a94e13b00a89ce3b149e0bcaa2dbfd4`, respectively. A local `git hash-object /usr/share/common-licenses/GPL-2` produced that same SHA, establishing that the saved snapshots' license-file bytes match the standard GPLv2 text. The tree objects do not establish whether another README, file header, or author statement grants “or later.” The `c42dbe4…` [GitHub tree URL](https://github.com/sk-zk/TruckLib/tree/c42dbe4f2d6bfb7b87c9ff1199c3cf5b7d1e27b0) did not load in the browser; a tree SHA in a URL or raw-file path should not be treated as a commit pin.

The historical TruckLib README specifies GPL v2, Core/Models defer to TruckLib, and all three project files package their LICENSE. No inspected operative notice grants later versions. - **Unknown — derivative boundary:** a documented binary layout, field offset, enum value, or format behavior can be used to implement interoperability. A close translation of expressive control flow, structure, comments, or other protectable code may carry upstream GPL obligations. The [deeper comparison](IMPLEMENTATION_INDEPENDENCE_ASSESSMENT.md) now records that work and its limits, including the short token formula and source-informed schema handling. The [GPLv2 text](https://opensource.org/license/gpl-2.0) and [FSF FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#TranslateCode) explain the consequence if there is a translation, but do not classify this codebase automatically.

## Release considerations and implementation of the choice

1. Read the now completed [technical source/derivation review](IMPLEMENTATION_INDEPENDENCE_ASSESSMENT.md) and decide whether its bounded assurance is sufficient for the intended release. If it is materially uncertain and a permissive license is desired, seek qualified legal review or written permission from the relevant rightsholder before presenting permissive terms as covering the whole tool.
2. State the scope clearly: Python code, authored documentation, configuration examples, and tracked icons need an explicit inclusion or separate notices. AI-generated icon art and Ford-themed depictions should be reviewed independently for rights and trademark presentation; a software license cannot guarantee rights in every depicted element. Keep game, DLC, map-mod, and extracted assets outside the grant and outside the tracked repository. Generated `.scs` packages can contain source-owned resources; the tool's code license does not grant redistribution rights to those resources. [GPLv2 section 0](https://opensource.org/license/gpl-2.0) also says program output is covered only when the output itself is a work based on the program.
3. The AGPL-3.0-only full license, copyright/version/scope notice, README, package metadata and third-party notices are now in place under ADR-0016. Preserve them when distributing the project. If GPL-covered upstream code is adapted, retain upstream copyright/license notices and mark changed files. Make the preferred modification source and any necessary build/install scripts available with distributed executables as [GPLv2 sections 1–3](https://opensource.org/license/gpl-2.0) require. If Extractor is later bundled, review its separate binary/source distribution obligations then; the present subprocess invocation does not itself bundle it.

**Decision implemented:** AGPL-3.0-only, selected by the maintainer for strong copyleft including modified network-service versions. This policy supersedes the earlier permissive recommendation without changing the technical evidence. The technical audit is complete at its documented scope; a stronger legal assurance remains a separate optional step. Future licenses for code owned by the maintainer do not retract previously granted rights or override other contributors' rights.
