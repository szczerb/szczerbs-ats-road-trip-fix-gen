# Open-source license recommendation

**Research date:** 2026-10-18. **Status:** recommendation for the maintainer; no repository license has been selected or applied. This is a provenance and compatibility assessment, not a legal determination.

## Recommendation

**Prefer `GPL-2.0-only` for the Python tool if the source comparison finds a substantial translation or adaptation of TruckLib, TruckLib.Models, or TruckLib.Core implementation.** It matches the minimum clearly documented upstream version and preserves a straightforward copyleft distribution path. First verify the grant at the exact source revisions and preserve their notices. The Python language does not by itself make translated code independent: the [FSF's translation guidance](https://www.gnu.org/licenses/gpl-faq.en.html#TranslateCode) treats a code translation as a modification, and [GPLv2 section 0](https://opensource.org/license/gpl-2.0) expressly includes translated code in a work based on the program. This recommendation does not decide whether these particular Python files are derivatives; that requires a side-by-side comparison of protected implementation choices, not merely matching file-format facts.

**If the comparison establishes independent implementation from format facts alone,** the maintainer can choose a permissive license for their own tool. `MIT` is the simpler option; `Apache-2.0` adds an express patent grant and more notice requirements. Both would permit proprietary reuse, unlike GPL copyleft. Apache-2.0 presents a practical compatibility problem if any GPLv2-only implementation is later incorporated: the [Apache Software Foundation](https://www.apache.org/licenses/GPL-compatibility.html) reports that Apache-2.0 is incompatible with GPLv2. Even with an independent implementation, `GPL-2.0-only` remains an available deliberate policy choice if the maintainer wants downstream modifications distributed under the same terms.

| Candidate for this tool | When it fits | Material constraint |
| --- | --- | --- |
| `GPL-2.0-only` | A conservative choice if protected GPLv2-only implementation was adapted, or if the maintainer wants strong copyleft for wholly original code | Give recipients the GPL text, preserved notices, modification notices where relevant, and corresponding source when distributing object code. It does not authorize third-party ATS assets. |
| `GPL-2.0-or-later` | Only after an applicable upstream grant explicitly allows later versions, or for separable original code when that broader grant is intended | Do not infer “or later” from the sample application paragraph at the end of a generic GPLv2 `LICENSE`. |
| `MIT` | Independent, owned implementation with a preference for minimal downstream conditions | It cannot relicense adapted GPL implementation as MIT; preserve copyright and permission notices. |
| `Apache-2.0` | Independent, owned implementation with a preference for an express patent grant | It cannot relicense adapted GPL implementation as Apache-2.0 and is incompatible with GPLv2-only combined code. Maintain license and applicable notices. |

`GPL-3.0-only` or `GPL-3.0-or-later` is not a safe whole-tool default while GPLv2-only provenance remains possible. The exact `only`/`or-later` grant matters. [GPLv2 section 9](https://opensource.org/license/gpl-2.0) permits later-version choice when the **program** specifies that choice; the standard license's end-of-file instructions are an example for authors, not a grant by every repository that includes the text. If the author of the upstream implementation has granted `GPL-2.0-or-later` in operative notices, a GPLv3 option may become possible after reviewing all applicable files and dependencies.

## Evidence and limits

- **Observed locally — current workspace, 2026-10-18:** `README.md` describes a Python 3.11+ standard-library tool. `src/ats_road_trip/archive.py` executes a separately installed sk-zk Extractor process for HashFS; the executable and ZIP are ignored under `local_outputs/`. `THIRD_PARTY_NOTICES.md` identifies TruckLib, TruckLib.Models, and TruckLib.Core as research sources. `src/ats_road_trip/map_sector.py`, `overlap_fuel.py`, `rest_stops.py`, and `courier_locations.py` document particular source-guided layouts. There is no root `LICENSE`. These facts narrow the review; neither separate-process use nor an “independently written” description proves that every parser is copyright-independent.
- **Documented — upstream pages inspected 2026-10-18:** [TruckLib's README](https://github.com/sk-zk/TruckLib) says GPL v2. The [TruckLib](https://github.com/sk-zk/TruckLib/blob/master/LICENSE), [TruckLib.Models](https://github.com/sk-zk/TruckLib.Models/blob/master/LICENSE), [TruckLib.Core](https://github.com/sk-zk/TruckLib.Core/blob/master/LICENSE), and [Extractor](https://github.com/sk-zk/Extractor/blob/master/LICENSE) repository listings identify GPL-2.0 and link GPLv2 license files. TruckLib's [project file](https://github.com/sk-zk/TruckLib/blob/master/TruckLib/TruckLib.csproj) points its package license to that file. These pages establish the GPLv2 baseline, but a generic GPLv2 text or GitHub classifier alone does not establish an `or-later` grant. Extractor's [2026-07-29 release](https://github.com/sk-zk/Extractor/releases/tag/2026-07-29) is the separately downloaded version recorded by the workspace.
- **Observed locally — historical source snapshots, 2026-10-18:** the saved GitHub tree API responses at `local_outputs/research/overlap/trucklib-tree.json`, `trucklib-models-tree.json`, and `trucklib-core-tree.json` report tree SHAs `c42dbe4f2d6bfb7b87c9ff1199c3cf5b7d1e27b0`, `6f09e0eb5c687202ffde0595e434675c455830e8`, and `85e810f66a94e13b00a89ce3b149e0bcaa2dbfd4`, respectively. These are **tree objects, not verified commit IDs**. All three trees point `LICENSE` to Git blob `d159169d1050894d3ea3b98e1c965c4058208fe1`. A local `git hash-object /usr/share/common-licenses/GPL-2` produced that same SHA, establishing that the saved snapshots' license-file bytes match the standard GPLv2 text. The tree objects do not establish whether another README, file header, or author statement grants “or later.” The `c42dbe4…` [GitHub tree URL](https://github.com/sk-zk/TruckLib/tree/c42dbe4f2d6bfb7b87c9ff1199c3cf5b7d1e27b0) did not load in the browser; a tree SHA in a URL or raw-file path should not be treated as a commit pin.
- **Unknown — operative upstream version grant:** before applying a license, map each historical tree to its actual commit or release and inspect its `README.md`, project metadata, relevant source headers, and author notices, including the corresponding TruckLib.Models and TruckLib.Core snapshots. Record the resolved commit IDs and any operative version notices. Do not turn the standard GPLv2 how-to text into evidence of an upstream later-version grant.
- **Unknown — derivative boundary:** a documented binary layout, field offset, enum value, or format behavior can be used to implement interoperability. A close translation of expressive control flow, structure, comments, or other protectable code may carry upstream GPL obligations. Compare the actual Python parser and serializer functions against the specific C# files used; document which portions are format facts and which implementation choices were adopted. The [GPLv2 text](https://opensource.org/license/gpl-2.0) and [FSF FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#TranslateCode) explain the consequence if there is a translation, but do not classify this codebase automatically.

## Release prerequisites after the maintainer chooses

1. Complete and record the pinned source/derivation review. If it is materially uncertain and a permissive license is desired, seek qualified legal review or written permission from the relevant rightsholder before presenting permissive terms as covering the whole tool.
2. State the scope clearly: Python code, authored documentation, configuration examples, and tracked icons need an explicit inclusion or separate notices. AI-generated icon art and Ford-themed depictions should be reviewed independently for rights and trademark presentation; a software license cannot guarantee rights in every depicted element. Keep game, DLC, map-mod, and extracted assets outside the grant and outside the tracked repository. Generated `.scs` packages can contain source-owned resources; the tool's code license does not grant redistribution rights to those resources. [GPLv2 section 0](https://opensource.org/license/gpl-2.0) also says program output is covered only when the output itself is a work based on the program.
3. Add the chosen full license and unambiguous copyright/version notices, and update `README.md`, package metadata, and `THIRD_PARTY_NOTICES.md`. If GPL-covered upstream code is adapted, retain upstream copyright/license notices and mark changed files. Make the preferred modification source and any necessary build/install scripts available with distributed executables as [GPLv2 sections 1–3](https://opensource.org/license/gpl-2.0) require. If Extractor is later bundled, review its separate binary/source distribution obligations then; the present subprocess invocation does not itself bundle it.

**Decision still needed from the maintainer:** whether to publish under the conservative GPLv2 path after source review, or to commission the independence review needed before choosing MIT or Apache-2.0. No `LICENSE` file is added by this recommendation.
