## Commit messages

Commit coherent, verified milestones locally without asking for routine confirmation. This is a single-contributor repository with the maintainer-configured GitHub origin `szczerb/szczerbs-ats-road-trip-fix-gen`, reported private on 2026-10-18. Read-only remote inspection is allowed for requested audits. Commit authorized work locally; do not push, replace the remote or change visibility without user direction. Use `master` directly for small documentation changes and stable milestones. Use a `codex/` branch for substantial or experimental tooling; use worktrees only where concurrent edits benefit from checkout isolation. Merge verified work locally, and preserve unvalidated experiments on a clearly reported branch. Prefer the existing checkout and share ignored original inputs read-only rather than copying archives into worktrees.

Use meaningful messages that let a future reader understand the change without opening the diff. Prefer a concise subject and a body for non-trivial commits. For broad, checkpoint, architectural, or first-project commits include:

- Major areas created or changed and why the change exists.
- Important user feedback, caveats, or direction that affects interpretation.
- Verification performed, when relevant.

Avoid vague subjects such as "scaffold foundation" unless the body explains what was scaffolded and why.
